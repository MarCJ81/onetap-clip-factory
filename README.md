# 원탭 클립 팩토리 (OneTap Clip Factory)

**긴 가로 영상 하나 → 세로 숏폼 클립 여러 개.**
강의·브이로그·게임·인터뷰 녹화를 넣으면 죽은 초를 지우고, 장면 컷을 찾아 클립으로 나누고,
9:16으로 피사체를 따라 리프레임한 뒤 자막까지 얹어 **실제 H.264 MP4 파일**로 뽑는 브라우저 완결 도구입니다.

- 22호기 **원탭 숏폼 스튜디오**(대본 → 새 숏폼 제작)와 역할이 다릅니다. 이쪽은 **이미 찍어 둔 긴 원본을 잘라 쓰는 공장**입니다.
- 라이브: <https://marcj81.github.io/onetap-clip-factory/>
- 가입 없음 · 서버 업로드 없음 · API 키 없이 무료 모드 100% 동작.
- Pro(선택): OpenAI · Gemini · Claude · 자체 서버를 연결하면 같은 버튼이 더 좋은 제목·훅을 만듭니다.

## 1. 한 번에 무엇이 나오나

| 결과물 | 설명 |
|---|---|
| `.mp4` 클립 N개 | 9:16 (1080×1920 / 720×1280 / 608×1080), H.264, 24·30fps. 무음이 빠지고 자막이 구워진 실제 파일 |
| `.zip` | 완료된 클립을 한 번에 묶어서 저장 |
| `.srt` | 편집한 자막을 원본 타임코드로 내보내기 |
| 클립 제목·훅·해시태그 | 무료 AI 맛보기 또는 내 Pro API 로 생성, 카드에 바로 적용 |

영상·음성은 **서버 전송 0건**입니다. 디코딩·분석·인코딩·저장이 모두 사용자의 브라우저에서 일어납니다.

## 2. 다섯 단계

| 단계 | 하는 일 | 조절 |
|---|---|---|
| 01 SOURCE | MP4·WebM·MOV 드래그&드롭, 또는 **데모 VOD 생성**(32초, Canvas+WebAudio) | 유튜브는 yt-dlp 명령 1클릭 복사 |
| 02 DETECT | 20ms 단위 음량으로 **죽은 초** 감지, 표본 프레임 히스토그램으로 **장면 컷** 후보 | 무음 임계치·최소 무음·말소리 여백·컷 감도, 클립 길이·개수 |
| 03 REFRAME | 열별 **피부톤 + 움직임 + 중앙 가중**으로 9:16 크롭 중심을 추적, 속도 제한 곡선으로 부드럽게 이동 | 피사체/움직임/중앙, 부드러움, 줌 1~1.6× |
| 04 CAPTION | SRT/VTT 불러오기, 타임코드 인라인 편집, 쇼츠 스타일 4종 | 옐로 임팩트 · 클린 화이트 · 블랙 박스 · 키커 라임 |
| 05 RENDER | 클립별 순차 렌더, 진행률·용량·소요 시간 표시, 개별 MP4 / ZIP | 해상도·fps·자막 포함 |

### 데모 VOD
외부 파일을 받지 않습니다. 누르는 순간 Canvas로 장면 5개(스튜디오·화면 공유·인터뷰·B-롤·아웃트로)와
움직이는 피사체를 그리고, OfflineAudioContext로 말소리 5블록과 **무음 6구간**을 합성해
mediabunny로 H.264 MP4로 인코딩합니다. 그래서 무음 제거·장면 컷·추적·자막·렌더를 한 번에 시험할 수 있습니다.

## 3. 실제 계산 방식

### 무음(죽은 초)
- Web Audio `decodeAudioData` → 채널별 20ms RMS 봉투 → dBFS.
- 기본 임계치 −38dB, 최소 무음 380ms, 말소리 여백 90ms.
- 임계치 아래가 최소 길이 이상 이어지면 제거 대상. 여백은 무음 쪽으로만 밀어 말끝을 보존합니다.
- 남긴 구간이 떨어져 있으면 클립은 **여러 원본 구간을 이어 붙인 하나의 출력**이 됩니다. 렌더·자막 매핑 모두 이 타임라인을 기준으로 계산합니다.

### 장면 컷
- 표본 프레임(최대 260개)을 128×72로 줄여 16구간 밝기 히스토그램 + 밝기 변화량을 계산.
- 중앙값 + 2.6×MAD 로 적응 임계치를 잡고, 650ms 이내 중복은 가장 강한 것만 남깁니다.
- 클립 경계는 1.3초 이내의 컷 후보에 붙습니다(스냅).

### 9:16 리프레임
- 클립마다 6fps로 열(column) 지도를 만듭니다. 열마다 피부톤 픽셀 비율, 이전 표본 대비 움직임, 중앙 가중치를 합성.
- 가장 강한 열 주변 ±8열의 가중 중심을 크롭 중심으로 사용. 특징이 없으면 중앙으로 복귀.
- `buildCurve`가 지수 평활 + 데드존 + 표본당 최대 이동(0.055)으로 카메라 팬을 만듭니다. 순간 이동 없이 따라갑니다.
- 크롭 사각형은 원본 비율과 9:16을 비교해 가로/세로 중 필요한 쪽만 잘라 냅니다. 줌은 크롭을 좁힙니다.

### 렌더
- `CanvasSource`(H.264) + `AudioBufferSource`(AAC, 없으면 Opus) → `Mp4OutputFormat`.
- WebCodecs가 없는 브라우저에서는 렌더 버튼이 비활성되고 이유를 표시합니다(분석·미리보기는 계속 동작).
- 프레임은 원본을 `seek`해 그립니다. 무음이 빠진 구간은 `sourceTimeAt()`으로 매핑합니다.
- 자막은 미리보기와 **같은 함수**로 그려 WYSIWYG를 보장합니다.

## 4. 솔직한 한계

- **얼굴 인식 모델은 넣지 않았습니다.** 피부톤·움직임 추적은 가볍고 빠르지만, 얼굴이 작거나 피부색이 배경과 비슷하면 중앙으로 돌아갑니다.
- **자동 음성 인식(ASR)은 없습니다.** 쓰던 SRT/VTT를 올리거나 직접 입력하세요. 자동 자막을 넣으면 모델 파일(수 MB)을 로컬에 넣어야 해서 이번 범위에서 제외했습니다.
- 장면 컷은 표본 기반이라 서서히 밝아지는 구간은 놓칠 수 있습니다.
- 유튜브 링크는 브라우저에서 직접 받을 수 없습니다(CORS·약관). yt-dlp로 받은 파일을 끌어다 놓으세요.
- 아주 긴 영상(1시간 이상)은 프레임 표본을 260개로 제한합니다. 파형은 전체를 계산합니다.
- 소리 분석은 파일 전체를 메모리에 올립니다. 1시간이 넘는 원본은 브라우저 메모리가 부족할 수 있습니다.
- AAC 인코더가 없는 브라우저(일부 Linux Chromium)는 MP4 안에 **Opus 오디오**로 저장합니다. 영상은 H.264 그대로입니다.
- 렌더는 원본을 프레임마다 `seek`해 그립니다. 아주 긴 클립(45초)을 1080p로 뽑으면 1~2분 걸릴 수 있습니다.
- 일부 소프트웨어 렌더링 환경(가상 머신·GPU 없는 헤드리스)에서는 큰 화면 전환·스크린샷 순간 렌더러가 불안정할 수 있어, 무거운 블러 효과를 쓰지 않도록 만들었습니다.

## 5. 파일 구조

```
clip-factory/
  index.html        공장 · 클립 시트 · 가이드
  styles.css        Factory Console 디자인(다크/라이트)
  core.js           순수 계산: 무음·컷·클립·추적·자막·훅 파싱 (node에서 테스트)
  media.js          원본 열기, 오디오/프레임 표본, 추적 곡선, 썸네일
  demo.js           내장 데모 VOD 생성(Canvas + OfflineAudioContext + H.264)
  render.js         9:16 프레임·자막 그리기, MP4 인코딩, ZIP
  app.js            화면·상태·큐·AI 연결
  engines/          free-ai.js · pro-api-connector.js · pro-studio.js
  assets/vendor/    mediabunny · wavesurfer · jszip (로컬, 런타임 CDN 0건)
  assets/fonts/     IBM Plex Sans KR woff2
  privacy.html      개인정보 처리방침
```

테스트 하네스(`test.js`, `uitest.py`)와 `preview-*.png`는 **로컬 작업 폴더에만** 두고 `.gitignore`로
공개 저장소에서 뺍니다. 저장소에는 사이트 파일만 올라갑니다.

## 6. 실행·검사

정적 파일만으로 동작합니다. 로컬 서버로 열면 됩니다.

```bash
cd apps/clip-factory
python3 -m http.server 8080
# http://127.0.0.1:8080/
```

```bash
node test.js          # 단위 테스트 + 개인정보/외부요청 위생 검사 (213개 확인)
python3 uitest.py     # 헤드리스 Chrome E2E 113개 확인, preview-*.png 저장
```

배포된 사이트를 그대로 검사하려면 `UITEST_BASE=https://marcj81.github.io/onetap-clip-factory` 를
넘겨 같은 스위트를 라이브 URL에 돌립니다(로컬 서버를 띄우지 않습니다).

`uitest.py`는 1440×900과 390×844에서 콘솔 에러 0, 외부 요청 0, 가로 넘침 0을 확인하고,
데모 VOD 생성 → 분석 → 9:16 프리뷰(추적·자막) → 실제 MP4 렌더(파일 헤더·크기·해상도·길이) → ZIP → 자막 편집 → AI 훅 모의 응답까지 검사합니다.
실측(이 개발 환경, 헤드리스 Chrome):
- 데모 32초 생성 + 분석: 약 14~16초 (인코딩 + 무음/컷 분석 + 추적 곡선 + 썸네일)
- 15초 클립 1080×1920 렌더: 약 16~18초
- 15초 + 10.4초 클립 720×1280 렌더: 약 24초
- 결과 크기: 1080p 15초 ≈ 3.4MB, 720p 15초 ≈ 2.1MB

저장되는 스크린샷: `preview-desktop.png` · `preview-desktop-clips.png` · `preview-desktop-render.png`
`preview-mobile.png` · `preview-mobile-clips.png` · `preview-pro.png` · `preview-light.png`

## 7. 프라이버시

- 영상·음성 서버 전송 0건, 첫 화면 외부 요청 0건. 폰트·라이브러리 모두 로컬.
- 영상·음성·자막 파일은 브라우저 밖으로 나가지 않습니다.
- 무료 AI 맛보기(`free-ai-taste.onetap-ai.workers.dev`)를 누를 때만 클립 자막에서 뽑은 텍스트와 길이, 무작위 방문자 식별자가 전송됩니다. 자세한 내용은 `privacy.html`.
- Pro 키는 sessionStorage(선택 시 localStorage)에만 저장되고, 연결한 제공자에게 브라우저에서 직접 요청합니다.
- 광고·분석·쿠키 없음.
